# AI 破界实验室界面优化设计说明

## 1. 目标

在不改变实验机制、数据规则、操作结果和学习证据逻辑的前提下，统一优化首页、四个实验页、能力图谱页与演示页的视觉、排版和学习引导。

改版需要同时达到以下效果：

- 参考用户提供的未来 AI 实验基地风格，形成更强的进入感和探索欲。
- 让初中生能快速理解“当前做什么、为什么做、观察什么、下一步去哪里”。
- 保留现有实验的全部交互与计算逻辑，不增加外部 AI 接口。
- 在桌面、平板和手机尺寸下避免固定导航、提示卡、图表、按钮和正文发生遮挡或重叠。

## 2. 范围与边界

### 2.1 本次修改

- 全站颜色、背景、字体层级、留白、圆角、阴影和状态样式。
- 顶部导航、侧边导航、手机底部导航和学习进度展示。
- 首页欢迎区、四个实验入口、实验四步法和小智助手区域。
- 实验页标题区、步骤轨道、任务说明、操作卡片、结果解释和下一步行动区域。
- 面向初中生的引导文案，使用短句和生活化表达。
- 响应式布局、滚动安全间距、横向溢出和层叠顺序。

### 2.2 本次不修改

- `lib` 中的实验算法、评分、推荐权重、结果计算和证据生成规则。
- 学习状态的数据结构与 `localStorage` 保存方式。
- 四个实验的任务数量、核心操作、输入输出和完成条件。
- 外部账号、外部 API、后端服务或付费能力。

## 3. 已确认的设计方向

### 3.1 视觉方向

采用“深色未来大厅 + 明亮实验卡片”的混合方案：

- 全站外壳、导航和首页欢迎区使用深蓝、靛蓝和少量青色发光效果，提供未来实验基地的沉浸感。
- 实验任务、表单、数据控制台和解释内容使用偏白、浅蓝或对应关卡浅色背景，降低长时间阅读负担。
- 四个实验使用稳定的识别色：表情捕手为蓝色，算法读心局为紫色，真假侦探社为橙色，校园智能体为绿色。
- 装饰效果服务于层级，不使用影响文字可读性的强光、复杂背景或持续动画。

### 3.2 引导方式

采用“小助手 + 就地提示”：

- 小智是贯穿全站的学习助手，但不替学生完成实验。
- 每个实验阶段在操作附近说明四件事：`你现在要做`、`你要观察`、`这说明什么`、`接下来`。
- 每个阶段只保留一个最显眼的主操作按钮；次要操作降低视觉权重。
- 引导提示每段不超过两句话，先用日常语言解释，再保留必要术语。

## 4. 信息架构与组件

### 4.1 全站外壳

- 顶部栏：品牌、当前位置或简化导航、学习进度和竞赛演示入口。
- 桌面侧栏：实验地图、四个实验和能力图谱；当前页面使用关卡色突出。
- 手机底部导航：保留五个核心入口，正文底部预留安全间距。
- 隐私说明：继续明确本地匿名学习、不采集姓名和真实浏览记录。

现有路由和导航目标保持不变，不新增路由依赖。

### 4.2 首页

首页首屏由四层组成：

1. 未来感欢迎区：欢迎语、核心价值、一个主按钮和一个“怎么实验”次按钮。
2. 小智助手：简短说明会陪学生完成四个挑战。
3. 四个实验入口：使用关卡识别色、通俗任务描述、成果提示和明确入口。
4. 实验四步法：先预测、改变量、找证据、说发现。

首屏优先产生行动欲望，不在欢迎区堆叠过多概念说明。

### 4.3 实验页

实验页沿用现有内容和交互，重新组织为统一骨架：

1. 页面标题：关卡编号、任务名称、一句话目标和教学模拟说明。
2. 步骤轨道：清楚显示当前步骤、已完成步骤和后续步骤。
3. 当前任务卡：说明本步动作和完成标志。
4. 原有实验操作区：保留按钮、表单、拖拽、图表与计算行为。
5. 小智提示区：桌面端位于操作区旁边，手机端进入正文流。
6. 结果解释区：先显示结果，再用“为什么变化”和“我发现”帮助学生总结。
7. 下一步区：只突出一个主行动，避免多个同权重按钮造成犹豫。

四个实验共享骨架，但不强行统一各自不同的交互组件。

### 4.4 能力图谱与成果

- 保留现有雷达图、成果卡和证据时间线。
- 将评价术语配上简短解释，避免只显示等级和抽象维度。
- 空状态明确告诉学生从哪个实验开始，以及完成后会看到什么。
- 本地数据清除仍保持二次确认，不改变原有行为。

## 5. 数据流与状态

改版不引入新的业务状态。现有 `LearningProvider` 继续负责：

- 读取和保存本地学习状态。
- 记录实验操作与学习证据。
- 计算全站完成进度。
- 向首页、实验页和能力图谱提供相同数据。

新增的界面状态仅限导航菜单开合、局部提示展开和视觉选中状态，不改变实验结果。能从现有数据直接推导的信息继续在渲染时推导，不复制为新的长期状态。

## 6. 响应式与滚动安全规则

### 6.1 桌面端

- 顶部栏和侧栏可以固定，但主内容必须用明确的 `margin` 或 `padding` 避让。
- 小智提示栏仅在主内容宽度足够时作为右侧栏显示；宽度不足时变为正文卡片。
- 双栏操作区使用 `minmax(0, 1fr)`，避免图表或长文字撑破网格。
- 固定元素设置明确层级，弹层和菜单不得被导航遮挡。

### 6.2 平板端

- 实验主区与结果侧栏改为单栏。
- 小智提示移动到当前任务卡之后。
- 四关首页卡片由四列变为两列。

### 6.3 手机端

- 侧栏隐藏，使用固定底部导航。
- 主内容底部至少预留 `72px` 加安全区，最后一个按钮不会被导航覆盖。
- 小智提示不悬浮，进入正常文档流。
- 步骤轨道允许横向滚动或显示精简标签，不压缩成难读文字。
- 图表、结果表、按钮组和表单全部改单栏；按钮保持足够触控高度。
- 页面禁止意外横向滚动，长文本和图表容器允许内部换行或受控滚动。

## 7. 可访问性与文案标准

- 正文字号、对比度和行高适合连续阅读；重要内容不只依靠颜色区分。
- 交互控件保留清晰的悬停、键盘焦点、选中、禁用和完成状态。
- 装饰图形使用隐藏语义或准确的替代说明。
- 尊重 `prefers-reduced-motion`，不使用必须依赖动画才能理解的反馈。
- 引导文案使用主动句和短句，例如“先写下你的猜测”，避免“请完成初始预测输入”等抽象表达。
- 结果解释使用“发生了什么—为什么—你能得出什么结论”的顺序。

## 8. 错误与空状态

- 未完成前置操作时，按钮禁用并说明还缺少什么。
- 没有学习证据时，成果页提供明确起点，不显示空白图表。
- 图表区域设置稳定高度，加载或数据为空时不造成布局跳动。
- 用户输入不完整时，在对应卡片附近提示，不使用遮挡整个实验的全屏错误。

## 9. 实现约束

- 优先复用现有 `Shell`、`PageHeader`、`StepRail`、`Panel`、按钮、提示和统计组件。
- 将新增视觉规则整理为设计令牌和少量可复用组件，避免在每个页面重复大段样式。
- 不引入新的大型 UI 框架或运行时依赖。
- React 组件中避免重复派生状态、组件内部定义组件和不必要的重渲染。
- 长页面的非首屏复杂区域可使用 CSS `content-visibility` 等低风险优化，但不能影响交互和可访问性。

## 10. 验收与测试

### 10.1 工程验证

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`

### 10.2 浏览器验证

至少验证以下页面：

- 首页 `/`
- 表情捕手 `/emotion`
- 算法读心局 `/recommender`
- 真假侦探社 `/detective`
- 校园智能体 `/agent`
- 能力图谱 `/results`
- 竞赛演示 `/demo`

每个页面检查：

- 页面标题和主要内容正确显示，无框架错误覆盖层。
- 控制台无相关错误和未解释警告。
- 主要按钮可操作，并出现预期状态变化。
- 首屏、页面中段和页面底部无固定导航遮挡、卡片重叠、文字截断或异常横向滚动。
- 桌面视口与至少一个手机视口均可完成核心操作。
- 首页和实验页视觉与已确认的设计方向一致。

## 11. 完成标准

只有在以下条件同时满足时，界面优化才算完成：

- 全站页面采用统一的新设计系统。
- 初中生能从当前页面直接知道操作、观察重点和下一步。
- 实验逻辑、数据结果和完成条件与改版前一致。
- 工程验证命令通过。
- 桌面与手机浏览器检查未发现重叠、遮挡、溢出或显示错误。
